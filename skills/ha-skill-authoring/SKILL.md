# Навыки для Home Assistant: создание и публикация

Навык — это процедура, которую другой человек сможет повторить на своей
установке. Всё, что знает только эта установка, в навык не попадает.

## Где что лежит

- **Публичный репозиторий навыков** и путь к его локальному клону указаны в
  `.claude/ha-local.md` проекта (раздел «Публикация навыков»). Если их там
  нет — спроси пользователя и допиши.
- Структура репозитория: `skills/<имя>/SKILL.md` (+ вспомогательные файлы),
  `README.md` со списком навыков.
- **Рабочие копии** для текущего проекта: `.claude/skills/<имя>/` — копия из
  репозитория, чтобы навык подхватывался в этом проекте.
- **Локальные заметки** `.claude/ha-local.md` — адреса, доступ (SSH, VPS),
  имена хостов, существующие дополнения и сущности, инвентарь устройств,
  где лежат пароли. Никогда не публикуется.

## ADR в этом же репозитории

Кроме навыков (процедур) в репозитории живут общие ADR (`adr/`) — записи
архитектурных решений с лучшими практиками. Разделение то же, что у навыков
и `ha-local.md`: общее решение → `adr/` публичного репозитория, конкретика
дома (замеры, адреса, имена сущностей) → локальная папка ADR проекта со
ссылкой на общий ADR. Проверки перед публикацией — те же. Значимое решение,
принятое в ходе задачи, оформляй ADR-ом, а не абзацем в отчёте.

## Когда предлагать навык

В конце задачи по HA, если получилась процедура, которую захочется повторить:
новый шлюз, типовая диагностика, обновление прошивки, настройка интеграции.
Одноразовые правки конкретного устройства — не навык, а запись в `ha-local.md`.

## Как писать

1. **Сначала раздели знания.** Всё, что вы выяснили, разложи в две стопки:
   - общее (как устроен Supervisor, где что ищется, грабли, проверки) → навык;
   - частное (IP, MAC, имена хостов и VPS, slug-и и entity_id этой установки,
     номера каналов и pan_id, логины, версии конкретных устройств,
     даты происшествий) → `ha-local.md`.
2. **Навык находит значения сам.** Вместо «шлюз 192.168.x.y» — команда, которая
   это выясняет, или «возьми из `.claude/ha-local.md`». Первый шаг любого
   навыка: «прочитай `.claude/ha-local.md`, если он есть».
3. **Примеры — только документационные**: IP `192.0.2.x`, `198.51.100.x`,
   `203.0.113.x`; заглушки в угловых скобках `<IP шлюза>`, `<из соседнего экземпляра>`.
   Проверки их пропускают.
4. **Пароли не пишутся никогда**, даже выдуманные. Вместо значения — заглушка
   в угловых скобках и где взять настоящее: `<из соседнего экземпляра>`.
5. **Frontmatter**: `name` — латиницей через дефис; `description` — что делает,
   когда применять и фразы-триггеры (по ним навык выбирается).
6. **Пиши для читателя, который не держит стек в голове**: термин при первом
   упоминании — с расшифровкой; причины граблей объясняй, а не только
   «не делай так». Каждая грабля — с тем, как её заметить.
7. **Проверки в конце навыка** обязательны: как убедиться, что всё
   сработало, а не просто записалось.
8. Язык — русский, как остальные навыки в репозитории.

## Проверка перед публикацией

Две проверки, обе из корня клона репозитория.

1. **Секреты и адреса — gitleaks** (https://github.com/gitleaks/gitleaks):
   ```sh
   gitleaks dir . -c .gitleaks.toml --no-banner -v
   ```
   Встроенные правила gitleaks ловят токены и ключи сервисов. Файл
   `.gitleaks.toml` в корне репозитория добавляет то, что gitleaks секретом не
   считает: IPv4 (кроме документационных), MAC, Zigbee IEEE, e-mail и пароль
   открытым текстом. Находок быть не должно.
2. **Значения из локальных заметок — grep.** gitleaks не знает, что
   `my-vps` или `sensor.kitchen_3` — ваши. Всё частное в `ha-local.md` пиши в
   `обратных кавычках`; тогда такие значения (с цифрой, дефисом, @, обратным
   слешем или http — то есть имена хостов, slug-и, entity_id, пути, URL)
   ищутся так:
   ```sh
   vals=$(mktemp)
   grep -oE '`[^`]+`' <путь к проекту>/.claude/ha-local.md | tr -d '`' \
     | grep -E '[0-9@-]|\\|http' | sort -u > "$vals"
   grep -rnF -f "$vals" skills adr README.md; rm "$vals"
   ```
   Пустой вывод — чисто. Общие слова вроде `python` сюда не попадают, и это
   нормально: они не выдают установку.
   **Находки обязаны блокировать публикацию**, поэтому push только через
   условие, а не после «поглядел глазами»:
   ```sh
   if grep -rnF -f "$vals" skills adr README.md; then echo "СТОП: разберись с находками"; else git push; fi
   ```
   Ложная тревога возможна, когда в `ha-local.md` в обратные кавычки попало
   публичное значение (имя файла из этого же репозитория, общеизвестный
   параметр) — тогда чинить надо заметки, убрав кавычки, а не игнорировать
   находку.
3. Каждую находку убери. Если значение общее для всех установок (например,
   идентификатор официального репозитория дополнений), всё равно лучше
   заменить его командой поиска.
4. **Прочитай навык целиком глазами.** Проверки не поймут названия комнат и
   устройств, имена людей, марку железа конкретного дома, даты происшествий.
   Их тоже убери.

## Публикация

```sh
cd <локальный клон>
git pull --ff-only
# положить/обновить skills/<имя>/, дописать строку в README.md
# проверки из раздела выше — обе чистые
git add skills/<имя> README.md
git commit -m "Add <имя> skill"      # или "Update <имя>: <что изменилось>"
git push
```

Затем скопируй навык в `.claude/skills/<имя>/` проекта, чтобы рабочая копия
совпадала с опубликованной. Правки делай в клоне репозитория и копируй в
проект, а не наоборот — иначе копии разъедутся.

Если навык публиковать не хочет пользователь или в нём неустранимо много
частного — оставь его только в `.claude/skills/` проекта и не пушь.

## Обновление существующего навыка

Если в ходе работы нашлась новая грабля или шаг устарел — поправь навык в
клоне, прогони обе проверки, запушь, обнови рабочую копию. Новые частные факты
допиши в `ha-local.md`.
